# Lab — Your First Day on a Data Team: Set Up a Tracked Project

**Skills assessed:** Git & Version Control, Terminal / Command Line (see this lab's own `RUBRIC.md`)

**Estimated time:** ~80 minutes (10 min intro · 55 min collaborative work · 15 min shareout)

## Scenario

It's your first week as a junior analyst on a small city-government data team. Before anyone hands you real data, your team lead gives you one onboarding rule: "If it isn't in git, it doesn't exist — and if all I see is one commit called 'final', I can't review your work."

Your task today is to prove you can set up a tracked project from nothing: a clean folder on your own machine, a repo with a README a teammate could actually read, a history that shows your work in real steps, and a copy on GitHub your lead can open without borrowing your laptop.

Work through it with your group — talk through what each command is doing and check each other's commit messages — but every Fellow builds and pushes their own repo. You'll compare histories with the whole class at the end.

*Work with your group, but complete and push/commit your own copy of this lab — collaboration is encouraged, a shared submission isn't.*

## Your Objectives

- **Stand up a clean workspace for the new project — not yesterday's demo folder**

- **Turn that folder into a tracked repo with a README a teammate could actually read**
  - *Hint: Make README.md however you like — VS Code, or straight from the terminal. From the terminal, `>` writes a brand-new file and `>>` adds to the end of one that already exists.*

- **Leave a history that shows three real steps of work, not one dump at the end**

- **Get the repo onto GitHub so your lead could open it without your laptop**
  - *Create your own empty GitHub repo first, then use the URL GitHub gives you — it's different for everyone, so there's no single URL to copy.*

## Share Out

Pull up your own `git log --oneline` and compare it with the people around you. Whose history would be easiest to hand a teammate who has never seen this project? What made the difference — the number of commits, where you chose to stop and commit, or the words in the messages? Then: what actually tripped you up today, and how did you figure out you were stuck?
